# TSK-003 — quiz-engine.js: state machine MCQ (STEP→REMEDIATION→NEXT→COMPLETION)

## Context

Parte di US-002 (Engine MCQ con state machine). Questo è il cuore logico del prodotto. La state machine gestisce il percorso studente: carica esercizi dal curriculum JSON, tiene traccia dei tentativi, attiva la remediation sull'errore, avanza al passo successivo, e si blocca dopo 3 tentativi falliti.

[^src: management/kanban/EP-001-core-adattivo-mcq-engine-llm/US-002-engine-mcq-state-machine/US-002.md §AC]

## Technical Specs

- **FE:** `engine.js` — modulo JS vanilla. Oggetto `QuizEngine` con stati: `STEP | REMEDIATION | NEXT | COMPLETION`
- **loadCurriculum(pdpLevel):** legge `data/curriculum-discalculia.json` e `data/pdp-levels.json` via `fetch`, seleziona gli step il cui campo `level` compare in `includes_levels` della policy di livello. Ritorna Promise.
  > **Correzione rispetto al piano (2026-09-14).** La spec originale filtrava per denominatore (L1 ≤4, L2 ≤10). Applicata alla lettera, esclude lo step transfer (1/5 vs 1/6) dal percorso L1 — cioè dal flusso principale della demo — e contraddice il test 2 di TSK-010, che dà per scontato che L2 veda step1 *e* step2. La progressione è ora un dato (`includes_levels` in `pdp-levels.json`), non logica nel codice: L1 → step1 + transfer, L2 → step1 + step2 + transfer. `max_denominator` resta nella policy come vincolo di authoring del contenuto.
- **submit(distractorId):** valida la risposta, legge `misconcepto_slug` dal distractor selezionato nel curriculum, passa a REMEDIATION se errato, passa a NEXT se corretto
- **Stop 3 tentativi:** counter per step corrente. Se `consecutiveErrors >= 3` → transizione a stato `STOPPED` (non REMEDIATION), mostra messaggio stop fisso, nessun pulsante Riprova
- **Messaggio stop:** `"Questo esercizio è meglio affrontarlo con il tuo insegnante o il tuo tutor di riferimento."` — hardcoded in engine.js come costante, mai da LLM
- **Nessun contenuto inline:** nessun testo di esercizio o misconcepto inline in engine.js — tutto via JSON

## Implementation Steps

1. In `engine.js`, definire `const STATES = { STEP, REMEDIATION, NEXT, STOPPED, COMPLETION }` e `const STOP_MESSAGE = "..."`.
2. Implementare `loadCurriculum(pdpLevel)`: `fetch('data/curriculum-discalculia.json')` → filter steps per level → store in `this.steps`.
3. Implementare la state machine: `currentState`, `currentStepIdx`, `consecutiveErrors`.
4. Implementare `submit(distractorId)`: se corretto → `consecutiveErrors = 0`, vai a NEXT; se errato → `consecutiveErrors++`, se `>= 3` vai a STOPPED, altrimenti vai a REMEDIATION con `misconcepto_slug` del distractor.
5. Implementare `nextStep()`: avanza `currentStepIdx`, vai a STEP (o COMPLETION se finiti gli step).
6. Implementare `getStopMessage()` → ritorna `STOP_MESSAGE`.
7. Esporre API: `engine.loadCurriculum()`, `engine.submit()`, `engine.nextStep()`, `engine.getState()`, `engine.getCurrentStep()`.

## Definition of Done

- [ ] Selezionando il distractor corretto la state machine va in NEXT (non in REMEDIATION)
- [ ] Selezionando un distractor errato la state machine va in REMEDIATION con `misconcepto_slug` corretto
- [ ] Dopo 3 errori consecutivi sullo stesso step lo stato è STOPPED e `getStopMessage()` ritorna il testo corretto
- [ ] `grep -nE 'misconcepto|frazione|denominatore' engine.js` restituisce 0 risultati (nessun contenuto inline)
- [x] `loadCurriculum('L1')` carica `[step1, step3]` e `loadCurriculum('L2')` carica `[step1, step2, step3]` (coperto da `app/tests/e2e.mjs`)
