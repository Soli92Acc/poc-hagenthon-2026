# TSK-001 — Setup proxy CORS Python + smoke test OpenRouter (D1 gate)

## Context

Parte di US-001 (Setup e schema condiviso). P-A deve avere il proxy locale funzionante e la chiave API validata entro il minuto 10 (gate D1). Senza questo TSK nessun TSK che chiama OpenRouter può procedere.

[^src: management/kanban/EP-001-core-adattivo-mcq-engine-llm/US-001-setup-schema-condiviso/US-001.md §AC]

## Technical Specs

- **Infra:** `proxy.py` — mini-proxy Python ~30 righe, `http.server` con handler CORS, legge `OPENROUTER_API_KEY` da env, fa forward a `https://openrouter.ai/api/v1/chat/completions`, risponde alla stessa porta (default 8080)
- **Budget OpenRouter (gate D1+D3):** 2 req max per questo TSK — (1) chiamata `GET /api/v1/key` per verifica credito/limite, (2) una completion di prova con `openrouter/free`. Tenere un contatore fisico (sticky note) dal minuto 0.
- **Schema fixtures.json (D2):** dopo smoke test, P-A scrive `data/fixtures.json` con 1 chiave reale nel formato `step1-L1-denominator_magnitude` → testo `{headline, spiegazione, analogia}`. Questo lock di schema è il segnale verde per P-B di iniziare US-003.
- **Integration test D2:** eseguire `resolveRemediation("step1","L1","denominator_magnitude")` (funzione stub in 5 righe) → deve restituire il testo dalla chiave, non undefined, non errore.
- **Fallback D1:** se il proxy non risponde entro 15 min → dichiarare D1 fallita, passare a fixtures manuali (5-6 chiavi scritte a tavolino), stop tentativi API.

## Implementation Steps

1. Esportare `OPENROUTER_API_KEY` da env: `export OPENROUTER_API_KEY="sk-or-..."` (mai nel codice, mai committata).
2. Scrivere `proxy.py` (30 righe): handler con CORS headers + forward a OpenRouter + lettura key da `os.environ`.
3. Avviare: `python3 proxy.py` — verificare che risponda su `http://localhost:8080`.
4. Smoke test: `curl GET /api/v1/key` → verifica limite free tier. Poi 1 completion di prova con `openrouter/free` → verifica risposta parsabile con campi `headline`, `spiegazione`.
5. **Verifica json_schema support (D3):** aggiungere al prompt di prova `"response_format": {"type": "json_schema", ...}`. Se restituisce errore → usare parsing manuale per la fixture generation (TSK-009).
6. Scrivere `data/fixtures.json` con 1 chiave `step1-L1-denominator_magnitude`.
7. Eseguire integration test stub D2 → confermare oralmente a P-B che lo schema è locked.

## Definition of Done

- [ ] `proxy.py` avviato e raggiungibile su localhost:8080
- [ ] 1 chiamata di prova parsabile ricevuta da OpenRouter (req count: ≤2 totali)
- [ ] `data/fixtures.json` esiste con chiave `step1-L1-denominator_magnitude` contenente `{headline, spiegazione, analogia}`
- [ ] Integration test D2 passa: `resolveRemediation("step1","L1","denominator_magnitude")` restituisce testo atteso
- [ ] P-B confermato verbalmente che ha letto fixtures.json e il formato della chiave è allineato
- [ ] Contatore budget OpenRouter inizializzato (sticky note): N req = 2
