# TSK-021 — Verifica presidio confine clinico (grep gate + injection test + footer check)

## Context

Parte di US-011 (Presidio confine clinico). Questo TSK è una verifica eseguita da P-A dopo il test E2E (TSK-010). Conferma che i 5 invarianti del confine clinico siano verificabili meccanicamente: entry point unico per testi, single-writer pdpLevel, denylist funzionante, stop 3 tentativi, footer su tutte le view. Questo non è una feature da costruire — è una gate di sicurezza da eseguire e documentare.

[^src: management/kanban/EP-003-accessibilita-confine-clinico/US-011-presidio-confine-clinico/US-011.md §AC]

## Technical Specs

- **Verifica 1:** `grep -c renderRemediation explainer.js app.js engine.js` = 1 totale. Solo un punto nel codice chiama renderRemediation.
- **Verifica 2 — injection test:** modificare temporaneamente un valore in fixtures.json inserendo la parola "diagnosi" nel testo. Caricare l'app, far attivare quella chiave → verificare che `renderRemediation()` mostri il fallback pre-scritto e NON il testo con "diagnosi". Ripristinare il JSON dopo il test.
- **Verifica 3 — single-writer pdpLevel:** `grep -n "setItem.*pdpLevel" app.js engine.js explainer.js index.html` → deve restituire esattamente 1 risultato (solo in app.js, funzione form docente).
- **Verifica 4 — stop 3 tentativi:** simulare 3 tentativi falliti consecutivi → verificare che appaia il messaggio di stop e il pulsante Riprova sia assente dal DOM.
- **Verifica 5 — footer su tutte le view:** navigare `?role=student`, `?role=teacher`, `?role=parent` → il footer con testo Legge 170/2010 è visibile in viewport senza scroll in tutte e 3 le view.

## Implementation Steps

1. Eseguire: `grep -c renderRemediation *.js` → annotare il risultato (deve essere 1).
2. Injection test denylist: aprire `data/fixtures.json` in editor, aggiungere "diagnosi" nel campo `spiegazione` della prima chiave, salvare. Aprire app, far attivare quella chiave → verifica fallback mostrato. Ripristinare fixtures.json originale, salvare.
3. Eseguire: `grep -n "setItem.*pdpLevel" app.js engine.js explainer.js` → annotare (deve essere 1 risultato).
4. Simulare 3 errori consecutivi nello stesso step → verificare messaggio stop + assenza pulsante Riprova (inspect DOM: `#btn-retry` non presente).
5. Navigare `?role=student` → verifica footer visibile. Navigare `?role=teacher` → verifica footer. Navigare `?role=parent` → verifica footer.
6. Annotare esito di ogni verifica (PASS/FAIL) su carta o chat.

## Definition of Done

- [ ] `grep -c renderRemediation *.js` = 1 (PASS)
- [ ] Injection test: testo con "diagnosi" NON raggiunge il DOM — appare il fallback (PASS)
- [ ] `grep -n "setItem.*pdpLevel" *.js` = 1 occorrenza totale in tutto il codice (PASS)
- [ ] Stop 3 tentativi: messaggio visibile, pulsante Riprova assente dal DOM (PASS)
- [ ] Footer Legge 170/2010 visibile senza scroll in tutte e 3 le view (PASS)
- [ ] Tutti e 5 i check annotati come PASS prima di dichiarare la demo pronta
