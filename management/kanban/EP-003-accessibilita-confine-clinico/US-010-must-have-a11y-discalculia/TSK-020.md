# TSK-020 — A11y set B: number line CSS + stacked fraction + visibility:hidden scaffold + focus post-submit

## Context

Parte di US-010 (Must-have a11y discalculia). P-B implementa i componenti a11y più complessi: la number line CSS con posizioni precalcolate, la rappresentazione stacked fraction, e il focus management post-submit. La number line è il componente visivo centrale della capability dimostrativa.

Sequenza di taglio se il tempo è insufficiente: (1) stacked fraction → degrada a slash con gap ≥8px (-20 min); (2) sticky-top (-15 min). I rimanenti non si tagliano.

[^src: management/kanban/EP-003-accessibilita-confine-clinico/US-010-must-have-a11y-discalculia/US-010.md §Business Rules]

## Technical Specs

- **Number line CSS statica:** `<div class="number-line">` con `position: relative`, ancoraggi 0 (sinistra) e 1 (destra) come elementi fissi. Per ogni frazione da mostrare: `<div class="fraction-marker" style="left: {position_pct*100}%">` con `aria-label` parlato (es. aria-label="un terzo"). Usa valori `position_pct` dal curriculum JSON.
- **Stacked fraction ≥28px:** `<span class="stacked-fraction">`: numeratore (`<span class="num">`) sopra denominatore (`<span class="den">`) con barra orizzontale CSS, font-size ≥28px. `aria-label` parlato obbligatorio (es. "un terzo"). Candidato taglio: degrada a slash `1/3` con gap ≥8px tra cifre.
- **visibility:hidden scaffold in transfer:** per gli step training, la number line usa `visibility: hidden` (non `display: none`) quando `engine.getScaffoldVisible()` = false — il layout non shifta (box model preservato).
- **focus post-submit:** dopo il submit, spostare il focus sulla regione feedback: `document.getElementById('feedback-region').focus()`. La regione ha `tabindex="-1"` per permettere il focus programmatico.
- **Nessun punteggio numerico prominente:** non mostrare contatori di errori o percentuali in sessione.

## Implementation Steps

1. Scrivere il componente CSS `number-line` in `<style>` di index.html: `position: relative; height: 40px; background: linear-gradient(#ccc, #ccc) center / 100% 2px no-repeat`. Aggiungere punti 0 e 1 come `::before`/`::after` assoluti.
2. Scrivere funzione `renderNumberLine(fractions)` in `app.js`: per ogni frazione in input, creare un marker `<div>` con `style="left: X%"` e `aria-label`.
3. Implementare stacked fraction: `renderFraction(num, den)` → ritorna `<span class="stacked-fraction" aria-label="num/den parlato">...`. Se candidato taglio: ritorna `<span>num/den</span>` con gap CSS.
4. Integrare il visibility:hidden: quando il componente NL viene inserito nel DOM per step training, aggiungere/rimuovere la classe `invisible` (Tailwind: `invisible` usa `visibility:hidden`) in base a `engine.getScaffoldVisible()`.
5. Aggiungere `tabindex="-1"` su `#feedback-region`.
6. Nel submit handler (app.js): dopo aver popolato `#feedback-region` → `document.getElementById('feedback-region').focus()`.
7. Verificare layout non-shift: con number line `invisible`, verificare che il layout della pagina non cambi (confronto visivo con/senza).

## Definition of Done

- [ ] La number line CSS mostra 1/3 a destra di 1/4 — posizioni proporzionali corrette (1/3≈33% > 1/4=25%)
- [ ] Il componente number line nel transfer item ha `visibility:hidden` pre-risposta — il layout non shifta (confronto visivo)
- [ ] Stacked fraction (o slash fallback) ha `aria-label` parlato corretto (es. "un terzo") — inspect DOM
- [ ] Focus dopo submit si sposta su `#feedback-region` (screen reader lo annuncia con `aria-live="polite"`)
- [ ] DevTools animation tab: zero animazioni su elementi number line e fraction markers
