# TSK-016 — Wiring localStorage → aggregazione dati report docente

## Context

Parte di US-008 (Report post-sessione docente). P-A implementa la funzione di lettura e aggregazione dei dati di sessione dal localStorage, che il report HTML di P-B (TSK-017) consumerà. Zero chiamate di rete: tutto da localStorage.

[^src: management/kanban/EP-002-viste-per-ruolo/US-008-report-post-sessione-docente/US-008.md §Business Rules]

## Technical Specs

- **FE:** funzione `getSessionReport()` in `app.js`
- **Dati in localStorage (scritti dall'engine durante la sessione):** tentativi per step, misconcepto_slug per ogni errore, `solvedWithoutScaffold`
- **Output getSessionReport():** oggetto `{stepsData: [{step_id, attempts, misconceptErrors: [{slug, count}]}], transferOutcome: 'autonoma'|'non-autonoma'}`
- **Nessun punteggio numerico prominente:** il report non calcola "73% corretto" — restituisce fatti specifici (quali misconcepit e quante volte per step)
- **Aggiornamento engine.js:** durante la sessione, l'engine deve salvare in localStorage: `session_steps` array con `{step_id, attemptCount, misconceitos: [slug_list]}`. Questo va aggiunto a `engine.js` nei metodi `submit()` e `nextStep()`.

## Implementation Steps

1. In `engine.js`, aggiungere tracking nel metodo `submit()`: se risposta errata → appendere `{step_id, misconcepto_slug, timestamp}` a `localStorage.getItem('session_errors') || []`.
2. In `engine.js`, nel metodo `nextStep()`: salvare in localStorage `{step_id, totalAttempts}`.
3. In `app.js`, implementare `getSessionReport()`: legge `session_errors` e aggregazione per step_id, conta frequenze misconcepit, legge `solvedWithoutScaffold`.
4. Ritorna `{stepsData: [...], transferOutcome: solvedWithoutScaffold === 'true' ? 'Transfer completato autonomamente' : 'Transfer non completato autonomamente'}`.
5. Testare: simulare una sessione con errori → verificare che `getSessionReport()` ritorna i dati corretti.

## Definition of Done

- [ ] `getSessionReport()` ritorna un oggetto con `stepsData` e `transferOutcome` (verifica console)
- [ ] `stepsData` contiene le occorrenze di misconcepit per step (es. `{slug: "denominator_magnitude", count: 3}`)
- [ ] `transferOutcome` = 'Transfer completato autonomamente' se `solvedWithoutScaffold`='true'
- [ ] `getSessionReport()` non fa nessuna chiamata di rete (DevTools Network: zero req durante chiamata)
- [ ] Nessun campo numerico percentuale nell'output di `getSessionReport()`

## Dependencies

- TSK-014 — OutcomeTracker scrive `solvedWithoutScaffold` → wiring lo legge
- TSK-012 — il router deve esistere per coordinare la view docente con i dati di sessione
