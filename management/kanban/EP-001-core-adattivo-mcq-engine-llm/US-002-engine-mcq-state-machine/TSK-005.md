# TSK-005 — MCQ component: render domanda + opzioni + feedback placeholder

## Context

Parte di US-002 (Engine MCQ). P-B costruisce il componente HTML/CSS della schermata studente: la domanda (una sola per schermata), le opzioni in single-column, e la regione feedback (placeholder per ora — l'explainer.js la riempirà). Questo è il contenitore visivo su cui si appoggiano anche i requisiti a11y (US-010).

[^src: management/kanban/EP-001-core-adattivo-mcq-engine-llm/US-002-engine-mcq-state-machine/US-002.md §AC]

## Technical Specs

- **FE:** sezione `<div id="view-student">` in `index.html` + funzione `renderStep(step)` in `app.js`
- **Struttura MCQ:** `<h2>` con il testo della domanda, `<ol role="list">` di opzioni MCQ in single-column, gap ≥1.5rem tra le opzioni (Tailwind: `space-y-6`), pulsante submit disabilitato finché nessuna opzione selezionata
- **Regione feedback:** `<div id="feedback-region" aria-live="polite" aria-atomic="true">` placeholder vuoto — l'explainer la riempirà dopo risposta errata
- **Regione stop:** `<div id="stop-region" hidden>` per il messaggio di stop 3 tentativi
- **Accessibilità base:** ogni opzione è `<button type="button">` (non `<input type="radio">`) con stato selezionato via `aria-pressed`, focus outline 3px visibile
- **Styling:** nessuna animazione su elementi numerici, sfondo #ffffff, testo #1a1a1a

## Implementation Steps

1. In `index.html`, popolare `<div id="view-student">` con struttura: heading domanda, lista opzioni, regione feedback, regione stop.
2. In `app.js`, scrivere `renderStep(step)`: svuota `#view-student`, crea `<h2>` con `step.question`, loop distractors → crea `<button>` per ognuno con `data-distractor-id`.
3. Aggiungere listener click su ogni button: toggle `aria-pressed`, abilita il pulsante submit.
4. Aggiungere `<button id="btn-submit" disabled>Rispondo</button>` con handler che chiama `engine.submit(selectedId)`.
5. Scrivere `renderFeedback(text)`: popola `#feedback-region` con il testo (usato da explainer.js).
6. Scrivere `renderStop(message)`: mostra `#stop-region` con il messaggio, rimuove il pulsante submit dal DOM.
7. Testare con dati mockup hardcoded (non dal JSON) — verificare layout single-column e gap.

## Definition of Done

- [ ] Il componente MCQ è visibile nel browser con dati mock: domanda + 3 opzioni in single-column con gap ≥1.5rem
- [ ] Selezionando un'opzione il pulsante submit si abilita
- [ ] Il pulsante submit con 0 selezioni è disabled (inspect DOM: `disabled` attribute presente)
- [ ] `aria-live="polite"` presente sulla regione feedback (inspect DOM)
- [ ] Focus outline 3px visibile su tutti gli elementi interattivi (verifica tastiera: Tab → ogni button ha outline)
- [ ] Nessuna animazione visibile su elementi numerici (DevTools animation tab: zero)
