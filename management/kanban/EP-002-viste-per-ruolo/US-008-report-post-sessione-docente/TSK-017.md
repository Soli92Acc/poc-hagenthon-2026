# TSK-017 — Report HTML docente: misconcepit + frequenza per step + esito transfer

## Context

Parte di US-008 (Report post-sessione docente). P-B costruisce la UI del report che il docente vede dopo la sessione studente. Zero punteggi numerici prominenti: il report mostra fatti specifici (quali misconcepit, quante volte, per quale step) e l'esito del transfer task.

[^src: management/kanban/EP-002-viste-per-ruolo/US-008-report-post-sessione-docente/US-008.md §AC]

## Technical Specs

- **FE:** funzione `renderTeacherReport(reportData)` in `app.js`, sezione `<div id="teacher-report-section">` in `index.html`
- **Struttura report:** (1) heading "Sessione di [pdpLevel]", (2) lista per step con misconcepit e conteggio (es. "Step 1: denominator_magnitude rilevato 3 volte"), (3) riga esito transfer ("Transfer completato autonomamente" o "Transfer non completato autonomamente"), (4) NESSUN punteggio percentuale visibile
- **Dati:** letti da `getSessionReport()` (TSK-016) — nessuna chiamata di rete
- **Denylist:** nessun termine della clinical-denylist nel testo renderizzato — i nomi dei misconcepit usati nel report devono essere in linguaggio didattico, non clinico. Usare `misconceptions.json` per mappare `slug → nome leggibile`.
- **misconceptions.json:** creare `data/misconceptions.json` con `{"denominator_magnitude": "Confronto per grandezza del denominatore", "numerator_focus": "Focus solo sul numeratore"}` (senza terminologia clinica)
- **Accessibilità del report:** heading, list semantica (`<ul>`), nessun elemento interattivo nel report (read-only view)

## Implementation Steps

1. Creare `data/misconceptions.json` con mapping slug → nome in linguaggio didattico.
2. In `index.html`, nella sezione `#view-teacher`: aggiungere `<div id="teacher-report-section" hidden>` con struttura heading + `<ul id="report-steps-list">` + `<p id="report-transfer-outcome">`.
3. In `app.js`, implementare `renderTeacherReport()`: chiama `getSessionReport()`, carica `misconceptions.json`, popola la UI.
4. Modificare `renderTeacherView()`: se `localStorage.getItem('session_errors')` non è vuoto (sessione completata), mostrare il link "Vedi report sessione" e la sezione report.
5. Verificare che nessun testo del report contenga termini della denylist: `grep` sul DOM renderizzato (o inspeziona manualmente).
6. Verificare che il report sia read-only (inspect DOM: zero `<form>`, `<input>`, `<button>` nel report).

## Definition of Done

- [ ] Il report mostra: lista misconcepit per step con conteggio (es. "denominator_magnitude: 3 volte in Step 1")
- [ ] L'esito transfer è visibile: "Transfer completato autonomamente" o testo alternativo — coerente con `solvedWithoutScaffold` in localStorage
- [ ] Nessun punteggio numerico percentuale visibile nel report (inspect DOM)
- [ ] `data/misconceptions.json` esiste con almeno 2 slug mappati a nomi in linguaggio didattico
- [ ] Inspect DOM del report: zero `<form>`, `<input>`, `<button>` attivi (view read-only)
- [ ] Report generato senza chiamate di rete (DevTools Network: zero req)

## Dependencies

- TSK-013 — la view docente deve esistere per ospitare il report
- TSK-016 — la funzione `getSessionReport()` deve esistere per i dati del report
