# TSK-009 — Batch fixture generation 9 chiavi via OpenRouter (budget gate)

## Context

Parte di US-004 (Spiegazione adattiva da fixtures). La generazione delle fixtures è una operazione quasi-single-shot: preparare tutti i 9 prompt, eseguirli sequenzialmente, accettare il primo output valido per ogni chiave. Non c'è margine per tentativi ripetuti: il budget richieste OpenRouter è 50 req/giorno e il piano disciplinato prevede max 15 req in questo slot (incluse le richieste di D1 e D3 da TSK-001).

## Technical Specs

- **Modello pinnato:** `nex-agi/nex-n2.5-mini:free` con `reasoning: {enabled: false}` e `response_format: {type: "json_object"}` (coerenza registro linguistico: stesso modello per tutte le chiavi → stessa voce narrativa)
  > **Sostituzione rispetto al piano (D1, 2026-09-14).** Il pin originale `thinkingmachines/inkling-small:free` non è raggiungibile via API: OpenRouter risponde `403 — Gate Free Endpoints by Agentic Harness`. Scartati anche `nemotron-3-super` e `nex-n2.5-pro` (reasoning-only: consumano il budget token in ragionamento e troncano prima dell'output) e i due `gemma-4` (429 upstream su pool condiviso — **non usarli come fallback in demo**). Ledger completo in `app/openrouter-budget.md`.
- **9 chiavi target:** 6 canoniche (step1-L1-denominator_magnitude, step1-L2-denominator_magnitude, step2-L1-denominator_magnitude, step2-L2-denominator_magnitude, step1-L1-numerator_focus, step1-L2-numerator_focus) + 3 ad alta frequenza extra per denominator_magnitude (varianti analogia pizza L1, analogia metro L2, analogia pizza+metro L1L2)
- **Prompt schema:** richiesta con `response_format: json_schema` (`{headline: string, spiegazione: string, analogia: string}`). Se json_schema non supportato (rilevato in TSK-001) → parsing regex su output grezzo.
- **Vincoli prompt:** lingua italiana semplice (≤15 parole per frase), zero termini della clinical-denylist, analogia L1: pizza divisa in pezzi, analogia L2: metro lineare o equivalente, testo 40-50 parole per `spiegazione`.
- **Budget gate operativo:** contatore fisico (sticky note). Regola: se il totale req supera 35 a 1:25h → freeze live slot, dichiarare DEMO_MODE permanente per la demo. Non aggiungere mai più req per "migliorare" una fixture.
- **Fallback D3:** se <6 chiavi generate entro 1:25h → hardcode le chiavi mancanti come testi manuali nel JSON (scalabilità ridotta ma demo funzionante, dichiarato esplicitamente).

## Implementation Steps

1. Prima di iniziare: verificare contatore req corrente (da TSK-001: deve essere ≤3). Budget residuo per questo TSK: max 12 req.
2. Preparare i 9 prompt in un file di testo locale (prompt.txt) — un prompt per chiave, tutti pronti prima di fare la prima chiamata.
3. Per ogni chiave (loop sequenziale, non parallelo):
   a. POST a `http://localhost:8080/complete` con `{"model": "nex-agi/nex-n2.5-mini:free", "reasoning": {"enabled": false}, "messages": [...], "response_format": {"type": "json_object"}}`
   b. Parsare output (`{headline, spiegazione, analogia}`)
   c. Applicare `renderRemediation()` per verifica denylist
   d. Se denylist pulita → scrivere in `fixtures.json` con la chiave composta
   e. Aggiornare il contatore fisico
4. Se json_schema non supportato: estrarre JSON manualmente da testo libero con regex.
5. Verificare: `Object.keys(fixtures).length >= 6` (gate D3).
6. Verificare: almeno 3 fixtures hanno testi `spiegazione` di 40-50 parole (conteggio manuale su 3 chiavi).

## Definition of Done

- [ ] `data/fixtures.json` contiene ≥6 chiavi nel formato `step_id-level-misconcepto_slug` (gate D3)
- [x] Il modello usato per tutte le chiavi è `nex-agi/nex-n2.5-mini:free` (verificabile da log del proxy)
- [ ] Almeno 3 fixtures hanno `spiegazione` di 40-50 parole (conteggio manuale su 3 chiavi)
- [ ] Le spiegazioni L1 e L2 per lo stesso misconcepto usano analogie diverse (pizza vs metro)
- [ ] Contatore req OpenRouter aggiornato e totale ≤15 (comprendendo le req di TSK-001)
- [ ] `renderRemediation()` non ha bloccato nessuna delle 9 fixtures (nessuna denylist hit)
