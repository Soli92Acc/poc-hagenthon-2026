# TSK-008 — explainer.js: resolveRemediation() + chiave composta + fallback chain + denylist clinica

## Context

Parte di US-004 (Spiegazione adattiva da fixtures) e US-011 (Presidio confine clinico). Questo TSK costruisce il cuore della capability del prodotto: la funzione che trasforma un errore in una spiegazione targettizzata. Include anche il presidio clinico (denylist + unico entry point renderRemediation) che è il requisito di sicurezza più critico.

## Technical Specs

- **File:** `explainer.js` + `data/clinical-denylist.json`
- **clinical-denylist.json:** array di ~25 termini vietati: `["diagnosi","disturbo","deficit","riabilit","clinic","specialist","valutaz","certificaz","psicolog","neurolog","DSA","BES","patolog","dislessia","discalculia","disfasia","disprassia","screening","assessment","terapia","trattamento","guarigione","cura","diagnosi","sindrome"]`
- **resolveRemediation(step_id, level, misconcepto_slug):** (1) costruisce chiave `step_id-level-misconcepto_slug`, (2) cerca in `fixtures`, (3) se assente e `DEMO_MODE=false` → chiama live slot proxy, (4) se live slot fallisce → usa fallback testuale pre-scritto
- **renderRemediation(text):** UNICO entry point per qualsiasi testo di remediation che raggiunge il DOM. Carica `clinical-denylist.json`, cerca ogni termine nel testo (case-insensitive). Se trovato → usa fallback pre-scritto invece del testo, NON filtra parzialmente.
- **DEMO_MODE:** variabile globale `const DEMO_MODE = true`. In DEMO_MODE, la chiave non trovata usa immediatamente il fallback testuale senza chiamata di rete (zero req OpenRouter durante dev/test).
- **Fallback testuale pre-scritto:** testo fisso in italiano semplice che descrive l'errore nella comparazione di frazioni senza terminologia clinica.

## Implementation Steps

1. Creare `data/clinical-denylist.json` con l'array di termini.
2. In `explainer.js`, definire `const DEMO_MODE = true` e il fallback testuale.
3. Implementare `renderRemediation(text)`: carica denylist (o usa cache in-memory), check case-insensitive per ogni termine, ritorna `{text: sanitized}` oppure `{text: fallback, wasCleaned: true}`.
4. Implementare `resolveRemediation(step_id, level, slug)`: costruisci chiave, cerca in `fixtures` (oggetto caricato in memory da TSK-009), se non trovata e DEMO_MODE=true → ritorna fallback, se DEMO_MODE=false → chiama `fetch('http://localhost:8080/complete', ...)`, gestisci timeout (3s) → Tier 3 fallback.
5. Implementare `loadFixtures()`: `fetch('data/fixtures.json')` → cache in-memory `window.fixtures`.
6. Rendere `renderRemediation` accessibile globalmente: `window.renderRemediation = renderRemediation` — esiste UN solo entry point (verificabile con grep).
7. Integrare con engine: dopo `engine.submit()` in stato REMEDIATION, chiamare `resolveRemediation()` → passare risultato a `renderRemediation()` → passare testo a `renderFeedback()`.

## Definition of Done

- [ ] `data/clinical-denylist.json` esiste con almeno 20 termini
- [ ] `grep -c renderRemediation explainer.js app.js` ritorna 1 totale (un solo punto che chiama renderRemediation)
- [ ] Iniettando manualmente in fixtures.json un testo con "diagnosi", `renderRemediation` mostra il fallback (non il testo iniettato)
- [ ] Con `DEMO_MODE=true` e chiave non trovata, la UI mostra il fallback in ≤2s senza spinner infinito
- [ ] `const DEMO_MODE = true` è la configurazione di default nel file
