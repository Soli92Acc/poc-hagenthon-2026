# TSK-015 — Transfer item UI: MCQ senza number line + feedback post-risposta con NL

## Context

Parte di US-007 (Scaffold-fading e transfer task). P-B costruisce la UI del transfer item: il componente non mostra la number line PRIMA della risposta (fisicamente assente nel DOM, non visibility:hidden come per gli step training). Dopo la risposta, se corretta, la number line appare con le posizioni evidenziate. "Prova questa!" senza annunci del cambio di condizioni.

[^src: management/kanban/EP-002-viste-per-ruolo/US-007-scaffold-fading-transfer-task/US-007.md §Business Rules]

## Technical Specs

- **FE:** modifica della funzione `renderStep(step)` in `app.js` per gestire lo stato transfer
- **Number line assente (transfer):** quando `engine.isTransferStep()` = true, la sezione number line NON viene inserita nel DOM prima della risposta. Non è `visibility:hidden` — proprio non renderizzata. Questo è diverso dagli step training dove usa `visibility:hidden` per il fading.
- **Feedback post-risposta transfer:** dopo submit, se corretta → `renderFeedback("Prova questa! ✓")` + inserire nel DOM la number line con le posizioni di 1/5 e 1/6 evidenziate (usando i valori `position_pct` dal curriculum).
- **Titolo transfer:** usare "Prova questa!" come heading del step, senza alcun commento sul cambiamento di condizioni.
- **OutcomeTracker:** chiamare `engine.isTransferStep()` nel submit handler; se transfer e risposta → la vista docente potrà leggere `solvedWithoutScaffold` da localStorage.

## Implementation Steps

1. In `app.js`, nella funzione `renderStep(step)`: aggiungere branch `if (engine.isTransferStep())` che NON inserisce il componente number line nel DOM.
2. Per step transfer: usare `<h2>Prova questa!</h2>` come titolo.
3. Aggiornare il submit handler: dopo risposta su transfer step → chiamare `OutcomeTracker.recordTransferOutcome(isCorrect)`.
4. Se risposta corretta su transfer: dopo aver mostrato il feedback, inserire nel DOM la number line con i marker delle posizioni 1/5 (0.2) e 1/6 (0.167) evidenziati con un colore/bordo distinto.
5. Verificare con inspect element: prima della risposta, nessun elemento number line nel DOM del transfer step.
6. Verificare: dopo risposta corretta, la number line appare con le posizioni corrette.

## Definition of Done

- [ ] Inspect DOM durante transfer step (prima risposta): nessun elemento con id/class "number-line" nel DOM
- [ ] Il titolo del transfer step è "Prova questa!" (non contiene parole come "senza aiuto" o "difficile")
- [ ] Dopo risposta corretta al transfer: la number line è visibile nel DOM con marker per 1/5 e 1/6
- [ ] `localStorage.getItem('solvedWithoutScaffold')` = 'true' dopo risposta corretta (verifica console)
- [ ] Dopo risposta errata: `localStorage.getItem('solvedWithoutScaffold')` = 'false'

## Dependencies

- TSK-014 — `engine.isTransferStep()` e `OutcomeTracker` devono esistere prima di costruire la UI del transfer
- TSK-020 — la number line CSS (a11y set B) deve esistere per poter inserirla post-risposta
