# US-001 — Setup e schema condiviso (D1 e D2)

## Descrizione

Come team, voglio completare il setup tecnico e definire lo schema condiviso del file fixtures entro i primi 15 minuti, affinché i due sviluppatori possano lavorare in parallelo senza rischio di disallineamento silenzioso sullo schema dei dati.

Stima: P-A 15 min, P-B 15 min (parallelo totale). Slot: 0:00–0:15.

## Business Rules

- D1: entro il minuto 10, il proxy locale deve rispondere a una chiamata di prova al provider LLM con output parsabile. Se fallisce entro 15 minuti → si passa a fixtures manuali, zero ulteriori tentativi sull'API.
- D2: entro il minuto 15, il file fixtures.json deve esistere sul disco con almeno 1 chiave reale e un integration test che chiama resolveRemediation("step1", "L1", "denominator_magnitude") e riceve il testo corretto.
- Lo schema della chiave è immutabile dopo il lock: `{step_id}-{level}-{misconcepto_slug}`.
- Finché D2 non è risolto e confermato da entrambi, P-B non scrive contenuto nel curriculum JSON.
- Il proxy non espone la chiave API al contesto browser: la chiave risiede solo nel processo del proxy.

## Acceptance Criteria

- [ ] Il proxy locale risponde a una chiamata reale al provider LLM con un oggetto JSON contenente almeno i campi `headline` e `spiegazione` entro il minuto 10, OPPURE la dipendenza D1 è formalmente dichiarata fallita e il team procede con fixtures manuali.
- [ ] Il file `data/fixtures.json` esiste con almeno 1 chiave nel formato `step1-L1-denominator_magnitude` entro il minuto 15.
- [ ] La chiamata `resolveRemediation("step1","L1","denominator_magnitude")` restituisce il testo atteso dalla chiave (non undefined, non errore) — integration test passato entro il minuto 15.
- [ ] P-B conferma verbalmente di aver letto il fixtures.json e che il formato delle chiavi coincide con quello che userà nel curriculum JSON — accordo esplicito prima di procedere su US-003.
